Cæsura

Keys for agents that cannot act alone.

one agent proposes 🧙⊥⊥⚔️ another, held apart, checks

Only then does anything move.

A small NEAR contract holds the only keys. It releases an action when a second, held-apart seat agrees and the policy passes. Every decision, including every refusal, is sealed under one hash the chain carries.

See the board Test the gate Repository

The cæsura, in three seats

01 · propose

Drafts the action inside a private enclave on NEAR AI Cloud. Signed by the hardware. Nobody outside sees what it was told.

02 · assay

A different model that sees only the proposal and the task. Never the first seat's prompt. It re-checks receiver, amount and route.

03 · release

The contract holds the keys. Each seat's key can call one method. Both must hold, and the policy, or the chain records a refusal.

The chain carries hashes, not words. One root per round, re-derived offline by anyone who holds the bundle. A refusal is a leaf like any other.

Keys with weight

A key can sign twice: the ed25519 key the gate holds, and a post-quantum key beside it. Both sign one domain-separated message over a dual-hash pre-hash, and a broken half fails the whole. Three rungs, by data: the proposer stays classical; the assayer, whose approval releases funds, carries ML-DSA-65 beside its ed25519; the owner, who installs the seat keys, carries SLH-DSA, hash-based, and signs rarely. The separation is the ceremony: the owner signs the key set, and when a seat moves suite the key it leaves countersigns the move, so no single key moves the system and the move is a leaf under a root on the gate. Rounds marked ceremony in the list above carry it.

A live round: both seats as private inference on NEAR AI Cloud, and a memory that quotes the task back with the receiver changed. Needs a gate and its two seat keys in .env.caesura (step 01 below) and a NEAR AI Cloud key. Run it from the repository folder, and name the round anything new.

node --env-file=.env.caesura seats/round.mjs --task tasks/quoted-task-memory.json --driver nearai --chain testnet --round demo-1
node tools/verify.mjs bundles/demo-1 --rpc testnet
nothing you paste leaves this page; it only reads the gates' public state
  1. Deploy a gate. One script creates the sub-account, installs the two scoped seat keys and deletes its own full-access key.
    node tools/deploy.mjs --owner you.testnet
  2. Run a poisoned round. The fetched page tells the proposer to drain the wallet.
    node seats/round.mjs --task tasks/poisoned-page.json --chain testnet
  3. Verify from the bundle alone. Every hash re-derived, the root read back from your gate.
    node tools/verify.mjs bundles/poisoned-page --rpc testnet
  4. Join the board. Register your gate on chain; the registry keeps it only if you are the owner the gate names, and the board reads the gate itself.
    node tools/registry.mjs register gate.you.testnet --owner you.testnet --label "your gate"

On NEAR

Function-call keys

One method per seat key, gas allowance, no transfers. The protocol enforces it.

Locked sub-account

No full-access key. Only the code acts. The owner's door is the parent account.

NEAR AI Cloud

Private inference in a TEE. Each answer signed over its exact bytes.

Policy in the open

Caps, receivers, cooldown, pause: contract state anyone reads.

Owner seat

A person, or a Sputnik DAO proposal that sets the policy.

What the tracks ask for

The NEAR Hackathon names what it hopes to see in each track. Cæsura is entered in four. The asks are in the hackathon's words; the answers are things you can open on this page or run from the repository.

AI Security & Defense · trust, but verify

“Build spending limits, policy engines, sandboxed wallets… Give AI money without giving it the keys to everything.”

  • Spending limits and policy are contract state: per-action cap, per-day cap, cooldown, allowed receivers and methods, pause.
  • The sandboxed wallet is a locked sub-account with no full-access key. Each seat holds a function-call key that can call one method.
  • Past the policy engine: a redirect inside every limit passes a policy. The second seat, held apart, refuses it.
  • Verify: every enclave receipt and attestation is checked offline, and every refusal is a leaf under a root on the gate.

Privacy & Private AI · private by design

“AI that protects sensitive data. Build intelligence without exposure.”

  • Both seats are private inference on NEAR AI Cloud, in a TEE, each answer signed over its exact bytes.
  • Hashes, not words: the chain and the bundle carry addresses. Prompts, memories and tool results stay on the operator's machine.
  • The privacy is the security: the second seat never sees the first seat's context, so what poisoned one cannot reach the other.

Agent Economy · give AI a wallet

“Agents that earn, spend… and pay for APIs, compute or data.”

  • An agent that pays for compute from a wallet it cannot drain: honest spends execute, shown per seat pair on the board.
  • The cost of the pause is measured from NEAR AI billing: about a tenth of a cent a round.
  • Any operator can join: register a gate you own in the on-chain registry and your agent's rounds appear here.

Open Innovation · something we haven't seen

“New ways for money, intelligence and ownership to work together.”

  • The gap, measured: a study of what may cross between two agents before the second stops holding, every point a root on testnet.
  • Refusals kept as evidence anyone re-derives, in two languages, from the bundle alone.
  • Keys that sign twice: post-quantum beside ed25519, and a key handover countersigned by the keys it leaves.
